Startup launch

Turning on launch at startup registers the current executable path with the operating system. If you move the app later, the fix is simply to run it from the new location and toggle startup off and on again.

jump where-to-find-it jump platform-behavior jump repair

Where to find it

Inside the app, the control lives in Configuration under the Application section.

screen section control
Configuration Application Launch at startup, with the resolved executable path

Platform behavior

ASR Pro uses the normal operating-system startup mechanisms rather than inventing a custom launcher.

platform mechanism
Windows Electron startup registration, with portable builds resolving through PORTABLE_EXECUTABLE_FILE
macOS native Login Items registration against the current .app bundle
Linux writes an autostart desktop entry to $XDG_CONFIG_HOME/autostart/ or ~/.config/autostart/

Repair after moving the app

  • launch ASR Pro from the new path
  • open Configuration
  • toggle Launch at startup off
  • toggle it on again so the system record points at the new binary
The startup state is also reflected in asrpro-data/config/app-settings.json, but the authoritative fix is always to re-register from the currently running app.
